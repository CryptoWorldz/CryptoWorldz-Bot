# WORLDZ Wallet — native Android public-address beta

This APK is a standalone native Android companion, not the old WorldzApp WebView wrapper.

## Implemented
- Native eight-chain selector in the established order: Solana, XRP Ledger, Base, Ethereum, BNB Chain, Sui, HyperEVM, Robinhood.
- Save one existing **public address** per chain locally on the device, with basic format validation.
- Copy, share and remove public addresses.
- Open WorldzLaunchPad and DexScreener in the user's external browser.
- No WebView JavaScript bridge, no private key collection, no transaction authority.

## Not yet implemented
Wallet creation, HD derivation, secure secret storage, mnemonic recovery, live balance queries, chain RPC integrations, native trading, signing, minting, launchpad execution, hardware wallet support and production security audit. **Do not deposit funds into an address generated by this app: it does not generate any.** The app can store an existing public address but cannot control its assets.

## CI and distribution
The GitHub Actions workflow builds an Android **debug-signed** APK, verifies SHA-256 and uploads an artifact. This is for controlled device testing, not a publicly endorsed production wallet. Do not publish the debug key as a production release identity.

For direct Worldz distribution, generate a dedicated long-lived release keystore **outside GitHub/source control**, back it up securely, add encrypted CI signing secrets, build and verify a release-signed APK, test on actual devices, and publish a checksum and download page. Google Play approval is not needed for direct Android APK distribution, but Android sideloading consent and platform security restrictions still apply.

## Security
Public addresses are stored in Android app preferences and are not secrets. Android backup is disabled. Never request, log, or store recovery phrases in this beta. All blockchain transactions and launch actions remain gated pending independently verified security and chain-specific tests.

## Welcome Rewards (planned, disabled)
The versioned `welcome-rewards.v1.json` defines a **1,000,000 WORLDZ total cap** and a **proposed 1,000 WORLDZ per eligible participant** (maximum 1,000), subject to approval against the canonical 100M WORLDZ genesis allocation. Wallet creation alone does not qualify a person; a verified signature and one-per-participant anti-Sybil enforcement are required. No mint address, distribution wallet, funding, claim endpoint or payout mechanism has been activated. Marketing must say "planned" until claims genuinely open.

## Next secure self-custody milestone
Implement audited per-chain derivation and Android Keystore-backed encryption, device recovery/backup UX, biometric or device credential gating, wallet ownership signatures and transaction review. No mnemonic should be stored in plaintext, logs, clipboard or analytics. Gate every chain by independent tests before enabling transfers or minting.
