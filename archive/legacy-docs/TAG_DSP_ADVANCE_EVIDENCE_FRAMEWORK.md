# JayJayTeamDev TAG / Centrelink Evidence Framework

## Purpose

Prepare a factual support package showing the work completed on OneWorldz, CryptoWorldz and the Model-348 Command Centre. This framework does not assume approval and does not replace current advice from Services Australia or NSW Trustee & Guardian.

## Non-negotiable safeguards

- Essential living costs come first.
- A Centrelink advance is not proposed as funding for token purchases, DCA, market activity, member rewards, Treasury contributions or speculative crypto holdings.
- Crypto wallet limits are separate owner controls and are not evidence that money is available or should be spent.
- No historical work hours are guessed or reconstructed.
- Only timed work sessions, dated commits, pull requests, workflow results, deployments, receipts and clearly labelled self-reported records may be counted.
- No private keys, seed phrases, recovery codes or confidential financial credentials are included.
- Current Centrelink eligibility, advance amounts and repayment affordability must be confirmed directly before submission.

## Evidence sections

1. **Project identity and purpose**
   - OneWorldz and CryptoWorldz mission
   - Zed, Auto and G.R.A.C.E roles
   - Community, education and real-world impact objectives

2. **Verified work activity**
   - Timed sessions from `/workstart` and `/workstop`
   - Description of each task
   - Actual elapsed minutes only

3. **Development deliveries**
   - GitHub commits and pull requests
   - Supabase migrations
   - GitHub Actions test results
   - Hostinger deployments and runtime checks
   - MiniApp and Telegram command upgrades

4. **Efficiency and replacement cost evidence**
   - Feature delivered
   - Typical professional roles involved
   - Evidence of completion
   - Conservative external cost estimate recorded separately from actual spending
   - Never present an estimate as wages earned or money owed

5. **Actual project expenses**
   - Hosting
   - Domains
   - Approved software subscriptions
   - Transaction or deployment costs
   - Receipts and payment dates

6. **Budget and affordability**
   - Essential expenses protected first
   - Requested amount and proposed use
   - Fortnightly repayment impact based on current official figures
   - Separate personal, project, charity, Treasury, Reward and Investment controls

7. **Risk controls**
   - No automatic wallet transfers
   - No automatic payouts
   - No private-key storage in Zed, GitHub or Supabase
   - Buy-only DCA remains disabled until separately secured
   - Reward reserve locked during first-week testing
   - Public contribution verification awards no Legend Points

8. **Reporting and review**
   - Report income, business receipts and assets when required
   - Refer material budget changes to NSW Trustee & Guardian
   - Keep an auditable record of approvals, receipts and outcomes

## Evidence commands

- `/workstart DESCRIPTION`
- `/workstop OPTIONAL_EVIDENCE_NOTE`
- `/evidence CATEGORY | TITLE | RESULT | OPTIONAL_REFERENCE`
- `/workevidence`

## Submission rule

The final package should clearly distinguish:

- completed work,
- planned work,
- actual expenses,
- estimated professional replacement value,
- requested funding purpose,
- and activities specifically excluded from the funding request.
