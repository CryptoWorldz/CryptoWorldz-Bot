# WORLDZ MASTER IMAGE LIBRARY — CURRENT BUILD RULES

Status: clean-slate source policy, 12 August 2026.

## Hard rules

- Keep only current website-required artwork in GitHub.
- High-resolution originals and historical material belong outside the deployment repository.
- Do not ship retired ecosystem, board, or orphanage branding.
- `ImpactBased™` is the current purpose-led board identity.
- `Action Spreads Smile's Orphanage` is the current Reagan humanitarian identity.
- Blockchain pages use their matching approved blockchain artwork and canonical domain.
- Do not create semantic aliases by copying one image under multiple misleading filenames.
- No Base64 transport fragments, screenshots, generic placeholders, or blurred remote-preview dependencies.

## Preserved current visual anchors

- OneWorldz current master imagery.
- CryptoWorldz current Command Centre / Worldz imagery.
- ImpactBased current artwork.
- Matching blockchain Worldz artwork.
- Purple Diamond Crew Hope Chest artwork.

Reagan / Action Spreads Smile's Orphanage artwork should be selected or regenerated fresh from approved current references rather than inherited from retired branding.

## Social + combined donation-page plan

- Preserve exactly two current Reagan / Action Spreads Smile's Facebook destinations when their current URLs are verified: Reagan's current personal/public profile and the current Action Spreads Smile's page.

## Command Centre Ultimate™ plan

- Build a dedicated premium `Command Centre Ultimate™` MiniApp screen rather than treating it as another ordinary website panel.
- Keep the screen visually strong but operationally simple: Zed / Auto / Grace / Admin / Wallet / Markets / Missions / Rewards / Governance / Settings should remain obvious and uncluttered.
- Preserve the compact Telegram mini-button command experience: gateway slash commands open small button-driven action menus instead of forcing users to memorise long command lists.
- Preferred gateways remain `/zedstart`, `/zed`, `/auto`, `/grace`, `/admin`, `/admingrace`, and `/help`, with roughly five primary actions per gateway where practical.
- The MiniApp and Telegram command buttons should feel like two faces of the same Command Centre, not separate products.
- Wallet rollout stays security-first: signed-message authentication, no seed phrase or private-key collection, clear separation between read/view functions and authorised transaction actions.
- Public market pages may show live DexScreener charts without login; secure wallet login and trade actions belong in the separate Trade Centre.

## Treasury / funding guardrail

- `$500 per week` is a maximum operating/funding ceiling, not a required weekly target and not an assumption that the full amount will always be available.
- Any percentage-allocation model scales down proportionally to the amount actually funded for that week.
- A week may be partially funded or unfunded without creating a deficit, catch-up obligation, or pressure to reach the ceiling.
- No automated system may exceed the weekly ceiling without a deliberate owner-approved configuration change.
- Reporting should show `available this week`, `allocated`, `used`, and `remaining`, rather than presenting `$500` as expected income.

## Verification gate

A build, checksum, CI pass, upload, or automated browser test is evidence only. Production is successful only after the real public domain is checked in a normal browser on desktop and mobile and the rendered imagery, links, routing, and layout are visually accepted.
