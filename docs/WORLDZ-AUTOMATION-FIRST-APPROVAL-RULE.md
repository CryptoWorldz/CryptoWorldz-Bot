# WORLDZ AUTOMATION-FIRST APPROVAL RULE

**Effective:** 2026-10-04

Routine Worldz workflows must not depend on a human Admin pressing an approval button when the system can prove the required conditions automatically.

## Approval roles

- **ReXSECURE™** — security, scam, abuse and confidence checks.
- **ZED** — membership, workflow, mission and rules checks.
- **AUTO** — reward caps, budgets and automated execution checks.
- **G.R.A.C.E.** — content, destination, schedule and communication checks.
- **DipShit** — member guidance, completion and handoff checks.

Where the required automated checks pass, the workflow should proceed automatically and record the decision.

## Human Admin is not the default

Ordinary Raid completions, eligible RaidPoints, eligible ShillPoints, routine profile/wallet onboarding, routine scheduling and other machine-provable actions should not wait in a human approval queue.

Exceptions should be handled by automated rules first: duplicate protection, fraud/security signals, caps, missing evidence, invalid destinations, provider failure or temporary budget limits.

## Security boundaries that remain

This rule does **not** replace actual cryptographic authority. On-chain Treasury actions still obey their wallet/multisig signature thresholds. Private keys, seed phrases, provider credentials, emergency stops and other security controls are not bypassed.

The distinction is:

**Admin review bottleneck — remove where automation can prove the answer.**

**Cryptographic/security authority — preserve.**
