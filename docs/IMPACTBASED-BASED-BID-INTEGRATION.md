# ImpactBased and Based.bid Integration

Prepared: 5 August 2026  
State: **CONFIRMED FOUNDATION — PRIVATE PRODUCT FEATURES NOT ASSUMED**

## Current verified project position

- Public project identity: `ImpactBased`.
- Current project stage in Supabase: `preparing`.

- Alternate route supported: `https://impact.oneworldz.com`.

## Confirmed public Based.bid capabilities

Current public Based.bid interfaces present:

- Board creation.
- Token launch paths.
- Pool launch paths.
- Board rules, fees and access controls.
- Fee Builder settings describing dynamic fees, holder rewards, buybacks, custom wallets and advanced protection.
- Initial-buy and market-cap controls in public launch interfaces.
- Public token and board pages across more than one supported network context.

These items may be described as Based.bid public capabilities, subject to the exact options shown at launch time.

## Features not yet verified as available to this project

Do not describe the following as working until confirmed through an official Based.bid interface or written developer confirmation:

- Board rename from Charity.Based to ImpactBased.
- Private API or webhook access.
- Automatic Zed mission creation from Board events.
- Automatic token registry updates.
- Solana paired with wXRP.
- Flash Launches.
- Dynamic liquidity or value-as-trust launch models.
- Every proposed cross-chain launch route.
- Automatic Diamond Buy Auto activation after a launch.

## Prepared integration flow

1. A project is reviewed through ImpactBased.
2. The approved launch destination and terms are recorded.
3. The public Based.bid launch page is created manually through the verified interface.
4. The official contract address, chain, pair and public links are independently verified.
5. The token is added to `ecosystem_tokens` with an honest launch status.
6. CryptoWorldz and the correct blockchain World display the record.
7. Zed may create a community mission after owner or authorised-admin review.
8. Auto remains disabled for that token unless the owner separately allowlists it for simulation.
9. Any future live purchasing would require another token-specific approval outside this package.

## Website rules

The ImpactBased portal must distinguish:

- **Confirmed Based.bid feature**

- **Discussed future capability**
- **Developer support required**

The existing Board remains linked during identity migration. The site must not claim that a renamed Board, API integration or unsupported chain option already exists.

## Zed integration

Safe current integration:

- Public ImpactBased link.
- Owner/admin reviewed missions.
- Governance discussion.
- Verified public token registry records.
- Public impact evidence links.

Not permitted:

- Governance controlling treasury signing.
- Automatic launch without owner review.
- Automatic token promotion based only on an unverified submission.
- Automatic Auto execution.

## Auto integration

SAFE LOCKED MODE may read an owner-approved, allowlisted contract and simulate a proposed schedule.

It cannot:

- Detect a new launch and purchase automatically.
- Sign or submit a transaction.
- create artificial volume.
- coordinate related wallets.
- guarantee price support or returns.
