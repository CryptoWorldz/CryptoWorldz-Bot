## Diamond Buy Auto readiness

### Architecture decision

Auto is a **separate Node service** using the same repository and Supabase project, with Zed acting only as the owner-facing control panel.

Reasons:

- A failure in Auto cannot take down Zed.
- Auto secrets are isolated from the Telegram bot environment.
- Deployment and rollback are separate.
- Owner controls can be audited independently.
- A future legal or security review can occur without rewriting Zed.

### SAFE LOCKED MODE guarantees

- `AUTO_MODE` must equal `safe_locked`.
- `AUTO_EXECUTION_ENABLED` must be false.
- Startup rejects any wallet private key, seed or signer secret.
- No transaction construction, signing or submission primitive exists.
- Database constraints force execution and signing false.
- Transaction signatures and signed payloads are constrained null.
- No token is allowlisted by default.
- All financial caps default to zero.
- Service starts paused with emergency stop active.
- Every simulation and owner control is audited.
- Only the exact owner Telegram ID and private Zed-to-Auto service token can call protected routes.
- Admins, partners and governance cannot access Auto controls.

### Prepared owner commands

- `/auto`
- `/autosimulate`
- `/autopause`
- `/autoresume`
- `/autoemergency`

These commands are deliberately excluded from the public BotFather command menu.

### Auto remains blocked from live purchasing

A future transaction-capable version would require a separate request, legal review, wallet-custody design, token-specific allowlisting, network-specific integration, independent security testing and a separate owner authorisation. This package does not provide it.
