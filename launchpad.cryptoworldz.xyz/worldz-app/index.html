MODULE REGISTRY

One app shell. Separate authority.

These modules are registered in the WorldzApp contract. An app tile never grants signing or financial authority by itself.

TREASURY PROFILES

Governance remains profile-specific.

Signer membership in one treasury does not silently make a person a signer of another treasury.

READ-ONLY CHAIN ADAPTERS

Observe first. Execute later.

These adapters define how WorldzApp will read balances, multisig configuration, proposal history and transaction state without exposing any signing or broadcast method.

IDENTITY + EXTERNAL WALLET CONNECTIONS

Your wallet comes to WorldzApp™.

Connect an external wallet from the WorldzApp surface. Stage 3 reads only the public address and network needed for the session. It does not request signatures, send transactions or collect custody secrets.

CAPABILITY FIREWALL

Deny unless explicitly enabled.

WorldzApp core can coordinate modules without becoming a master key. Mainnet actions remain gated at the module, treasury and blockchain level.

NON-NEGOTIABLE

WorldzApp never asks for:

  • Seed phrase
  • Private key
  • Recovery words
  • A universal key shared across blockchains

Wallet signing stays with the connected wallet, hardware device or native multisig system.
