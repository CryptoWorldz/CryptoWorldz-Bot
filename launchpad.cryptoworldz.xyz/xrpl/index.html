XRPL is not treated like Solana or EVM. This adapter uses XRPL trust-line tokens because they have production DEX and AMM compatibility. It never asks for or stores a wallet seed.

Testnet launch configuration

Connect GemWallet on XRPL Testnet. Use a dedicated issuer account and a separate hot/operational account.

Issuer approvals

Connect GemWallet to the issuer account. Two account-setting transactions are intentionally separate because XRPL AccountSet accepts one SetFlag at a time.

Hot-wallet trust line

Switch GemWallet to the hot wallet entered above, reconnect, then approve the trust line.

Issue supply

Switch GemWallet back to the issuer, reconnect, then issue the configured supply to the hot wallet.

Create XRPL AMM

Switch GemWallet to the hot wallet, reconnect, then create the Token/XRP AMM with the configured launch liquidity. AMM creation has a higher XRPL transaction cost than normal transactions.

No XRPL launch proof yet.

Mainnet gate

This first executable adapter is Testnet-only. Mainnet will use the same native transaction sequence after issuer/hot-wallet governance, Worldz fee-routing policy, public manifest and accounting/legal gates are approved. No secret keys belong in WorldzLaunchPad.
