Read this first: the token is not the whole machine.

Worldz deliberately separates the token mint from the market, routing, automation and proof layers. That keeps the canonical token simple while allowing newer technology to surround it without creating another token or silently changing its supply.

TOKEN LAYER

WorldzMINT™

Creates the canonical fixed-supply Solana mint, writes metadata, distributes disclosed genesis allocations, then permanently removes Mint and Freeze authority.

MARKET LAYER

Pool / Curve

Creates the place where a token trades: direct AMM liquidity, a bonding curve that later graduates, or another verified chain-native market route.

ROUTING + DATA

Jupiter layer

Wallet connectivity, swap routing, token discovery, price data and optional order automation sit around the token. They do not need to be embedded inside the mint.

PROOF + CONTROL

Worldz systems

Trust Orbit, Confidence Pulse, Worldz Proof, multisig controls and Command Centre show what is verified, what is changing and what remains locked.

Simple version: keep one canonical token. Add better trading, routing, analytics and automation around that same token. Do not create a second mint just to gain access to another product's launch interface.

Jupiter technology: where it fits

Jupiter is most useful as infrastructure around a canonical token: wallet access, execution routing, market data and automated orders. Worldz can adopt each capability independently rather than forcing token creation through one external launch product.

INTEGRATED

Jupiter Wallet + Solana Wallet Standard

WorldzMINT prioritises Jupiter-compatible Wallet Standard signing when available and supports the Jupiter Mobile/Reown path. The wallet remains the signer; Worldz does not request a seed phrase or private key.

CURRENT JUPITER API

Swap API V2 • Meta-Aggregator

Jupiter's current /order + /execute path lets Metis, JupiterZ RFQ, Dflow and OKX compete for execution. Jupiter can handle transaction landing and applies its real-time slippage estimation on the managed path.

CURRENT JUPITER API

Swap API V2 • Router

The /build route exposes raw swap instructions with Metis routing for integrations that need custom transactions, CPI or composability. This is the flexible path when Worldz needs to add its own instructions.

EXTERNAL SIGNALS

Tokens V2 + Jupiter Verify signals

Token search/discovery and verification signals help identify the correct mint. Trust Orbit treats Jupiter identity and organic-market data as independent external evidence — never as a Worldz or Jupiter endorsement.

CURRENT JUPITER API

Price V3

Jupiter's current price endpoint provides market price data by mint. Worldz can use price as one market input while keeping liquidity, concentration, authority and organic activity as separate evidence.

OPTIONAL FUTURE INTEGRATION

Trigger V2 • Limit Orders + DCA

Jupiter Trigger V2 supports vault-based price orders and DCA, including single limit orders, OCO / TP-SL structures, OTOCO chains and recurring time- or price-conditional swaps. This is an automation layer, not part of the token mint.

What about Jupiter Studio?

Jupiter Studio is an external token-launch product. It can be useful for creators who want Studio's own token/launch path. WorldzMINT exists so a Worldz token can keep one canonical mint and then use compatible Jupiter infrastructure around that mint. Creating another token in Studio merely to gain other Jupiter features would create a second mint, which is not required.

Why not put “all Jupiter tech” inside the token itself?

Because routing, market data, order automation and wallet connectivity are services/protocol layers that change over time. Keeping them outside the immutable mint lets Worldz upgrade integrations without changing supply rules or replacing the token.

Raydium + Meteora: the market engines

RAYDIUM

CPMM + LaunchLab

CPMM is a constant-product AMM for direct token/quote liquidity. LaunchLab is Raydium's bonding-curve launch system with configurable platform settings and graduation into an AMM market. Worldz Flash tests CPMM; Worldz Curve tests LaunchLab.

METEORA

DBC + DAMM v2

Dynamic Bonding Curve is a configurable virtual pricing curve that can graduate into DAMM v1/v2 after a real quote threshold is reached. DAMM v2 is Meteora's newer AMM with flexible liquidity management and position-based liquidity features. Worldz Curve Pro tests DBC → DAMM v2, while direct DAMM v2 architectures can work with an already-existing canonical mint.

Critical distinction: virtual curve liquidity is a pricing mechanism. It is not the same thing as withdrawable real SOL/quote liquidity. Worldz displays virtual curve state, real quote collected and graduated real LP separately.

Worldz CrossPair™ + OmniChain™

CROSSPAIR

Choose a verified quote asset.

CrossPair is the quote-asset layer. It separates the project token from the asset it trades against. A verified wrapped asset can be a quote without implying that the project token itself is backed by that asset.

OMNICHAIN

Chain-native first.

OmniChain is the shared project/proof architecture across Solana, EVM, XRPL and future chain adapters. It does not pretend every blockchain works the same way. Execution remains chain-native and each mainnet adapter is independently gated.

Fees: there are different kinds

Wallet-transfer tax

0% under the Worldz standard. Moving a token from one ordinary wallet to another is not the same thing as trading it in a pool.

Venue / protocol fee

A DEX or routing venue can charge its own protocol fee. That fee is external and must be shown separately rather than pretending Worldz controls money it never receives.

Supported project trading fee

A fee collected through a supported market route. Public creator launches operate inside the Worldz Safe Launch range. Specific Worldz-owned/test architectures can use a configured 2.00% trading-fee target without turning ordinary wallet transfers into taxable events.

Security + governance technology

SQUADS V4

Multisig treasury control

A multisig requires multiple authorised wallets to approve treasury or administrative actions. Worldz uses multisig proof so one hot wallet is not silently treated as the whole treasury governance model.

METAPLEX

Token Metadata

Solana metadata stores/discloses token identity such as name, symbol and metadata URI. WorldzMINT finalises metadata before permanently revoking token authorities.

FAIL-CLOSED

Release gates

If an execution adapter, fee route, lock, authority state, treasury route or proof cannot be verified, Worldz keeps the applicable mainnet action disabled instead of silently assuming it works.

Worldz Safe Launch Standard™

Fixed supply

Mint authority revoked after genesis. Freeze authority revoked/absent.

Founder limits

Public creator/team allocation ≤15% total, ≤5% liquid at genesis, with minimum cliff and vesting controls on the remainder.

Liquidity controls

Public creator liquidity allocation and lock requirements are checked before mainnet verification. Declared liquidity is not called real until the market account proves it.

No tax trap

0% wallet-transfer tax. Supported creator trading fees are constrained by the published platform limits and disclosed before execution.

Crypto words in normal English

CA / Mint AddressThe unique on-chain address identifying a Solana token mint. It is not the pool address.
SPL TokenA Solana token created under a Solana token program.
ATAAssociated Token Account — the standard token-holding account for a wallet + mint pair.
SOL / wSOLSOL is Solana's native asset. wSOL is SOL represented as an SPL token so token programs and AMMs can use it.
Quote AssetThe asset used to price/trade another token, such as SOL, wSOL or another verified asset.
LP / Liquidity PoolToken reserves that allow people to trade. LP value is real only when the assets actually exist in the pool.
AMMAutomated Market Maker — an on-chain market that uses a mathematical pricing rule instead of a traditional order book.
CPMMConstant Product Market Maker — a common AMM model where the pool balances determine price.
Bonding CurveA programmed price path used during launch before or instead of a normal liquidity pool.
DBCDynamic Bonding Curve — Meteora's configurable virtual launch curve that can migrate into an AMM.
DAMM v2Meteora's newer Dynamic AMM program for post-launch/direct liquidity, with flexible position and liquidity features.
GraduationThe move from a launch curve into its post-launch AMM/liquidity market after configured conditions are met.
Virtual LiquidityMathematical curve state used for pricing. It must not be confused with withdrawable real assets.
SlippageThe difference between the expected trade price and the actual execution price caused by liquidity and market movement.
Basis Point / bps1 basis point = 0.01%. Therefore 200 bps = 2.00%.
RPCThe network endpoint an app uses to read Solana and submit transactions.
Mint AuthorityThe key allowed to create additional token supply. Revoking it makes a fixed supply permanent.
Freeze AuthorityThe key allowed to freeze token accounts. Worldz Safe Launch requires it removed/absent.
MetadataPublic identity data such as token name, symbol, image/URI and related information.
MultisigA wallet/control account that needs multiple authorised approvals instead of one key deciding alone.
VestingA schedule controlling when allocated tokens become available.
LP LockA restriction preventing controlled liquidity from being withdrawn before the declared conditions are met.
Protocol FeeA fee charged by an external protocol/venue. It is separate from Worldz project economics.
Wallet-Transfer TaxA fee on ordinary token transfers. The Worldz standard sets this to 0%.
MainnetThe real blockchain using real assets and irreversible transactions.
Devnet / TestnetTesting networks used to prove code and flows without calling them production mainnet launches.
Fail-ClosedIf proof is missing or a check fails, execution stays blocked instead of assuming success.
